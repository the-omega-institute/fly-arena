# 实施路线与验收关卡

日期：2026-09-16。本文保留原始完整验收计划；当前已实现研究 MVP，实际通过项与未完成项见 [VALIDATION.md](VALIDATION.md)，不能把这里的完整科研/工程关卡视为全部通过。阶段按依赖推进，不能用计划文件、漂亮画面或单元测试替代真实闭环证据。

## 1. 推进顺序

```text
G0 来源与数据导入
  → G1 FlySpec / 编译 / 权重预算
  → G2 神经模型可变权重与数值对照
  → G3 单蝇具身闭环与因果验证
  → G4 网页与 AI 同一提交流程
  → G5 双蝇同世界 / 多地图 / 排名 harness
  → G6 Mac / 4060 性能与故障验收
  → G7 学习赛、进化赛与规模化
```

API 契约、页面结构与数据导入可以同步开展，但 UI 只能展示已知事实；G3 未通过前，不发布“真实脑控制竞技”宣传。CPU 先完成贯穿全链路的一场比赛，GPU 接入独立验证。

## 2. 阶段交付与退出条件

| 阶段 | 实际交付 | 通过条件 | 不通过时 |
|---|---|---|---|
| G0 数据与环境 | MaleCNS v1.0 下载 manifest、导入器、ID/edge 索引、Eon 对照 profile、环境锁 | 原始/派生 hash、统计、许可、符号未知比例和筛选报告齐全；重复导入一致 | 修复导入与数据口径；不伪造神经元规模 |
| G1 设计编译 | FlySpec schema、selector catalog、delta 编译、预算报告、不可变 artifact | UI 与文件提交等价；重叠 selector/tensor 不能绕过预算；非法数据拒绝；父代不被覆盖 | 缩小开放参数集合 |
| G2 神经模型 | 可持久 step 的稀疏 LIF 后端、基线 fixture、状态/trace | 固定刺激可重跑；权重修改改变下游响应；与参考模型对照解释一致 | 修正方程/积分/延迟；不直接上身体 |
| G3 具身闭环 | 单蝇感知编码、真实神经计算、固定 readout、步态与食物世界、真实回放 | 有限稳定轨迹；基本趋化/行走；脑输出消融影响行为；改权重效应可复现 | 检查 bridge 与读出；不可用隐藏脚本冒充脑控制 |
| G4 产品切片 | 网页 circuit 编辑、预算、版本发布、SDK、异步实验与结果查看 | 人和 agent 均提交同一格式，完整完成设计→编译→模拟→回放；错误可解释 | 保持私有 alpha，修复交互与接口 |
| G5 正式竞技 | 双蝇同世界、觅食/抢食/擂台、种子/换边、结果验证与榜单 | 接触/资源守恒、无 slot 顺序优势；verifier 重算一致；规则冻结且旧局可解释 | 有问题的玩法保持实验态，保留可用模式 |
| G6 工程化 | 原生 Mac CPU worker、4060 候选 worker、租约/故障、备份、观众测试 | 符合已冻结性能门槛；失败/迟到不重复评分；恢复成功；资源配额有效 | 降低并发或限制 trace/视觉；必要时开始 C++ 热点优化 |
| G7 研究扩展 | bounded plasticity、跨局进化、未知地图 benchmark | 学习不绕过预算，状态重置正确，泛化/适应经对照验证 | 保留固定权重赛道为主 |

## 3. 首轮有意义的实验

所有实验先做小规模诊断，再在看到评测结果前冻结种子、主要指标、失效条件和统计方法。下列样本数为初始工程计划，不是已证明具有统计功效的科研方案。

| ID | 实验 | 对照 / 主要记录 | 初始执行量 |
|---|---|---|---|
| E00 | 节点运行环境 | CPU/RAM/VRAM、OS、依赖、磁盘、可用余量 | 每候选节点一次，只读起步 |
| E01 | 数据重导入 | source hash、相同 edge ordering、计数与未知符号 | 同一输入两次 |
| E02 | 预算与编译 | 重叠 selector、delta 叠加、重复 ID、NaN/Inf、越界、threshold 单位 | 契约 fixture 与边界用例 |
| E03 | 神经参考与 mutation | 同 seed 刺激、指定边增减、silencing、spike rate/timing | 小型解析网络 + 真实图受控刺激 |
| E04 | 持续步进 / reset | 一次运行 vs 分段 advance、完整 reset、延迟队列与 PRNG | 同环境各 3 次 |
| E05 | 单蝇闭环因果 | baseline、脑输出关闭、选定 circuit 消融、同预算随机变异 | 每条件 5 seed 诊断；冻结后 20 seed 评估 |
| E06 | 双蝇同世界 | 真实接触、隔墙、扑空、同 tick 抢食、对称初态/交换 slot | 每几何/事件 case 多次固定重放 |
| E07 | 模式评分 | 资源守恒、同时死亡/离台、终局未整帧、相同分数、规则版本 | 每合法与非法事件 fixture |
| E08 | CPU/GPU 与容量 | 相同 input/state/profile、每玩家不同 W、1/2/4 场 | 冷启动 1 次 + warm 重复至少 3 次 |
| E09 | 任务故障 | lease 到期、旧 worker 完成、重复上传、NaN、OOM、对象缺块 | 每种故障注入至少 3 次 |
| E10 | 回放 / 数据恢复 | artifact 损坏拒绝、verdict 重算、同环境重跑、备份恢复 | 每种恢复路径真实执行 |
| E11 | AI 提交与展示 | agent 获取规则→设计→评测→提交；网页产生同等 artifact | 一个 SDK agent 完整流程；20 观众起步 |

E03 不以“所有后端都用了 0.275”当数值等价证明。E05 不以动作非零当网络有效证明。E08 神经 GPU、物理 GPU和视觉渲染各自计时，不能把总速度变化归因于一个组件。失败局和基础设施失败都保留在报告中。

时间步收敛、跨后端误差阈值与竞技效果的最小实用差异，在 pilot 后依据观察噪声制定，再对独立 seeds 验证。不能在看过正式评测结果后调整通过阈值。

## 4. 首个端到端产品切片

1. 导入真实 MaleCNS 并冻结 baseline 和纳入范围。
2. 用户打开 `/design`，复制 baseline，选择一个有来源的嗅觉相关 edge group，将权重设为 ×1.15。
3. 网页展示预算估算；服务端编译返回最终边数、成本、参数差异与 artifact digest。
4. 用户点击“单蝇觅食测试”；worker 排队运行，用神经网络的持续状态驱动真实身体。
5. 比赛返回食物摄入、路径、神经活动摘要、耗时和实际关节轨迹回放。
6. 用户保存版本；一个使用 SDK 的 agent 以相同规则产生另一个版本，执行相同实验。
7. 两只 frozen fly 在同一世界抢食，裁判依据事件评分；结果和回放出现在网页。

这个切片必须真实完成。若只是简化预览，UI 和实验记录明确写 preview，不进入官方榜单。

## 5. 语言与平台的决定时点

G0–G3：Python 3.12 起步，按实际可解依赖生成锁文件；FlyGym/MuJoCo 与 Eon benchmark 可使用独立环境，不强行合并全部 CUDA/GeNN/NEST 依赖。Mac 使用原生进程和 CPU 路径；不要把 Docker 中的 Linux 容器等同原生 macOS/Metal。

G2 定义神经 buffer/状态契约，G3 定义完整 step loop 和 checkpoint 语义。G6 用 profile 决定是否实现 `libflycore` 的 C++20 / CUDA；参考 Python/Brian2 实现保留。C++ 原型上线前需要相同刺激、状态、事件与任务指标的 differential checks。

一个正式赛季只有一个经过验收的运行 profile。若 GPU backend 使用不同 solver 或精度，先成为独立实验 profile，不自动混合 CPU 结果。

## 6. Heca / NyxID / Ornn 的接入次序

- 当前：NyxID 节点发现已完成；Mac Studio/Heca 已核实，Mac Studio 已运行私有 MVP；4060 SSH 已恢复并确认 RTX 4060 Laptop 8 GB，GPU 仿真后端待后续评测。运行证据见 VALIDATION.md。
- G0–G3：Heca 可用于开发与诊断，Arena worker 独立运行；不把计算任务寄托在某个聊天 agent 会话存活上。
- G4：NyxID 接用户/agent 身份，Arena 实现领域权限与 quota；SDK 可直接访问 API。
- G4–G5：提供 Ornn 可分发的 `fruit-fly-designer` skill，规定训练/验证 API、预算与 lineage；Ornn 接入不阻塞 SDK 用户。
- G6：公开部署时将 API/存储入口与家用 worker 分离，节点全部主动出站；Heca 停止不影响比赛是验收项。

## 7. 工作量与首要风险

以下为有 Python/仿真经验的小团队的粗粒度估计，G0–G3 后重新估计；不是交付日期承诺。

| 工作包 | 粗略工程量 | 主导不确定性 |
|---|---|---|
| 数据、FlySpec、budget、harness 契约 | 1–2 人周 | 源数据策略和 circuit catalog |
| 神经参考、动态权重、单蝇身体闭环 | 2–4 人周或更多 | 感知运动桥、数值稳定、模型到行为的可用性 |
| 网页/SDK/API/回放切片 | 2–3 人周 | 版本和异步任务体验 |
| 双蝇、多模式、排名和故障治理 | 2–4 人周 | 接触求解、评分漏洞、性能 |
| GPU/原生优化与学习赛 | 在 benchmark 后估计 | 硬件、不同 W batch、可塑性稳定 |

首要风险是**真实脑网络与身体的可用闭环**，其次才是吞吐；不应先花数周自研 C++ 引擎或大规模平台，再发现策略行为全由隐藏的运动脚本决定。

未解决项按能否阻塞下一阶段管理：MaleCNS 的符号/纳入策略和感觉运动映射阻塞 G2/G3；4060 的接入与性能只阻塞 GPU 实验；公网部署和 Ornn 不阻塞本地真实闭环。以实际运行证据调整后续范围。
