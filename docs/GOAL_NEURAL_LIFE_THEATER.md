# Goal: 生命体回放与神经剧场

> **用户确认的总目标（2026-09-19）**：用公开的真实果蝇神经连接组作为 canonical brain，让人和 AI 在其基础上修改神经参数、选择演化算法、设计数字果蝇，并把它们放入可渲染的三维竞技环境中竞争、学习和演化。每次设计都必须能回放为一条可观察、可复现、可审计的生命记录：用户能同时看到果蝇身体、感觉观测、脑区/神经元活动、动作、事件、资源变化和比赛结果，并能沿谱系解释一项修改如何影响行为。

本 Goal 的完成标准是“用户真正能使用并理解研究对象”，而不是只提供接口或一个抽象分数。第一优先级是可观看的单体觅食闭环，随后扩展到脑图编辑与预览、可选演化算法、双体竞技、AI 提交和 NyxID 一次性授权接口。实现继续以 Python、MuJoCo、NumPy/Numba 和 Three.js 为主，4060 承担长回放与批量评估，Mac Studio 承担交互服务；只有 profiling 证明必要时才迁移 C++/CUDA。

**当前状态**：Goal 仍在进行中。已有 30 秒可审计觅食回放、4060 射线视觉 staging 证据，以及 MuJoCo 食物接触证据；下一步必须把可见回放、设计预览和真实演化轨迹继续推进到用户可直接操作的 MVP。视觉仍是工程化观测，物理触碰虽然已经来自 MuJoCo 接触缓冲区，二者都还不能被宣称为已经校准的生物学神经输入。

## 目标

把 Fly Arena 从“提交果蝇、跑一段轨迹、得到一个分数”推进成可观察的数字生命实验场。用户应该能够设计一张基于真实果蝇连接组的大脑，把它放进三维环境，观察感觉输入、神经活动、身体动作和任务结果在同一条时间线上发生，并沿着生命谱系记录每一次设计和实验。

第一阶段的硬验收物是：一只用户设计的果蝇在三维场景中完成一次可见、可复现、可审计的觅食过程。它需要检测食物的视觉或气味线索，移动到食物附近，完成接触和摄取；用户同时能看到果蝇、食物、传感器、行为事件、大脑活动和最终结果。

## 当前版本与目标的差距

当前版本已经有 MuJoCo 物理场景、Three.js 三维显示、连接组编译、神经 trace、生命档案和演化记录，但回放仍主要显示身体轨迹、少量回路曲线和最终分数。现有短时实验没有稳定的食物接触与摄取机制，也没有把“传感器输入 → 脑区活动 → 动作 → 结果”串成一条可读的生命记录。

因此下一阶段的重点是可见的生命闭环，而不是继续增加孤立的优化器、账号或发布接口。

## 产品体验

用户打开一只果蝇的生命回放后，应看到：

- 具有身体、触角、足和口器的简化三维果蝇；
- 叶片、果实、障碍物、光照和多个食物源组成的三维环境；
- 食物产生可记录的空间气味场，并有视觉、嗅觉、触觉和接触传感器；
- 第一人称、跟随视角、自由摄像机和脑图视角；
- 可暂停、慢放、逐帧和拖动的时间轴；
- “发现气味”“改变方向”“进入食物范围”“接触食物”“成功摄取”等事件标记；
- 同一时刻的身体状态、传感器读数、脑区活动、动作输出和能量/食物变化。

用户点击一个事件时，界面应解释这一小段过程：例如检测到左前方气味后，嗅觉回路活动上升，下行运动回路随后偏转，若干百毫秒后进入食物接触范围。解释必须区分仿真观测、行为统计和研究者解释。

## 大脑可视化

165,122 个神经元和 25,563,197 条连接不能一次性以毛线团形式绘制。采用可展开的三层视图，同时保留完整真实连接图：

1. **全脑功能区域**：视觉、嗅觉、触觉、中央复合体、蘑菇体、学习/记忆、下行运动和输出等区域。颜色和亮度来自该次仿真的活动。
2. **神经元类别**：按 class、side、region 和投射方向展开具体类别，例如嗅觉投射、Kenyon cells、descending neurons 和 motor-related neurons。
3. **局部神经元与连接**：显示实际节点、兴奋/抑制方向、突触权重、输入输出以及用户修改的边。

LIF 使用脉冲密度和膜电位，rate 模型使用连续活动值和相对基线变化。前端可以统一显示“活动强度”，但必须保留原始模型语义，不能把连续 rate 虚构成 spike。

## 生命回放数据契约

每个采样点需要记录：

```json
{
  "t": 12.34,
  "body": {"position": [0, 0, 0], "heading": 1.42, "velocity": [0, 0, 0], "energy": 0.82},
  "sensors": {"olfaction": [], "vision": [], "touch": [], "food_distance": 0.34},
  "brain": {
    "circuits": [{"id": "olfactory", "activity": 0.71}],
    "neurons": [{"id": 1823, "activity": 0.92}],
    "top_edges": [{"edge": 77312, "flow": 0.81}]
  },
  "events": [{"kind": "odor_detected", "source_id": "food-03", "confidence": 0.8}]
}
```

浏览器不需要每帧接收全部连接。身体和传感器可按 10–20ms 记录，回路活动按 10–50ms 记录，事件窗口记录 top-k 神经元和边；完整活动作为可下载研究数据保存。每份回放必须绑定 connectome hash、brain model、mutation spec、optimizer、map、seed、physics version、decoder version 和 simulation commit。活动亮度只能来自这些记录。

## 竞技任务

先做完整的觅食任务，再扩展竞争：

### 觅食

- 30–60 秒三维环境；
- 2–5 个食物源和不同气味强度；
- 部分食物被障碍物遮挡；
- 食物有限，果蝇有能量消耗；
- 接近不等于吃到，必须完成口器接触和停留条件；
- 摄取增加能量和得分；
- 越界、卡住和能量耗尽有明确失败事件。

### 竞争与躲避

在觅食机制稳定后加入两只或多只果蝇、资源争夺、接触/攻击、受伤、逃避和资源控制。每个地图必须明确观察输入、可执行动作、成功/失败条件、分数以及需要记录的行为事件。

## 设计和训练

设计页分为两个层级：

- 普通模式修改嗅觉、视觉、记忆、探索、攻击、逃避和运动等功能回路，并显示真实脑区、预算和影响说明；
- 高级模式按神经元类型、区域和左右侧搜索连接，查看突触数、权重和修改前后差异，导出完整 FlySpec。

保存前提供固定刺激预览：左侧食物、右侧食物、气味增强、障碍物接近和对手出现。预览和正式竞技必须使用相同的脑模型和解码器。

训练算法仍然可选：随机搜索、CEM、遗传算法、Adam/BPTT、模拟退火和用户自己的插件。所有候选都必须经过真实环境评估，并同时记录神经目标损失、真实任务得分、摄取数、路径长度、能量消耗、传感器使用和失败原因。神经响应损失下降不能自动标记为竞技性能改善。

## 页面结构

回放页面采用四个同步区域：

```text
┌──────────────────────────────────────────┐
│             三维竞技场                    │
│       果蝇、食物、气味、障碍物、对手        │
├───────────────────┬──────────────────────┤
│ 行为与传感器曲线   │ 大脑活动图            │
│ 事件与状态         │ 回路→神经元→局部连接  │
├───────────────────┴──────────────────────┤
│ 时间轴：感知、决策、行动、接触、摄取、结果  │
└──────────────────────────────────────────┘
```

必须支持事件跳转、场景对象筛选、脑区筛选、两只果蝇对比、视频导出和原始 JSON/Parquet 下载。

## 分阶段验收

### 阶段 1：生命回放最小闭环

一只果蝇、一个觅食地图、30 秒以上仿真、传感器、食物接触/摄取、行为事件、三维身体和同步脑区活动。验收标准：用户能打开链接看到果蝇找到并摄取食物，并在同一时间轴看到相关活动。

### 阶段 2：大脑图浏览器

完成全脑区域、神经元类别、局部连接三层展开，显示真实突触权重、设计修改和回放活动。验收标准：用户能从摄取事件跳到对应脑区和局部连接。

### 阶段 3：设计后即时预览

设计页显示脑图，修改权重后显示差异，在固定刺激下预览活动传播和运动输出。验收标准：用户能看到一次修改如何改变大脑和动作。

### 阶段 4：真实双体竞技

两只果蝇同场争夺资源，各自保留完整事件和脑活动，可按时间比较大脑与行为。验收标准：比赛结果能由感知、转向、接触、摄取和能量过程解释。

### 阶段 5：行为目标演化和 AI 贡献

优化器针对真实任务目标进化后代，页面展示每代脑图差异和实际回放；AI 通过 API 提交候选，记录优化理由、参数和结果。验收标准：能从祖先追踪到后代，并判断改变是否真正改善了任务。

## 技术路线

暂不重写 C++。继续使用 Python、MuJoCo、NumPy/Numba、Three.js 和现有 API；4060 用于长任务、批量评估和高质量回放渲染，Mac Studio 提供交互服务。只有 profiling 证明神经计算热点并且接口稳定后，才考虑把明确的热点迁移到 C++/CUDA。

## 第一项必须交付的可见成果

下一次交付不能只是接口、数据库或统计分数。必须交付一条可以观看的生命记录：一只用户设计的果蝇在三维森林场景中检测气味、找到食物、接触并摄取；用户可以拖动时间轴，同时看到果蝇、食物、传感器、事件和大脑活动，点击事件可以展开相关脑区和连接，并下载对应的可审计研究数据。

## 当前实现进度：回放神经剧场第一增量

已完成第一条数据与界面增量：仿真每个记录帧现在保存左右气味、基于 MuJoCo 三维射线与障碍遮挡计算的左右视觉目标观测、MuJoCo 物理接触、最近食物距离和口器距离。视觉明确标记为 `raycast_engineered_observation_v1`；食物触碰来自注册的口器接触探针与静态食物几何之间的 MuJoCo contact buffer，标记为 `mujoco_food_contact_observation_v1`。两者都只进入回放与事件记录，不改变尚未经过独立校准的 LIF/rate 神经输入，神经桥保持已校准的双侧气味行为基线。每帧同时保存各功能回路活动和固定的规范神经元采样，`events.json` 记录气味检测、视觉目标、物理食物接触、摄取、出界和个体接触事件，裁判会校验这些事件的结构和数值。

回放页已增加 Neural theatre：传感器状态、可选择的功能回路、从 `/connectome/neurons` 读取的规范神经元/局部边显示样本、基于真实活动的节点亮度，以及可以跳转时间轴的事件按钮。为了保持历史回放和现有浏览器契约兼容，首屏事件时间轴从同一批记录帧推导；不可变的 `events.json` 仍然作为研究证据和下载资产保留。当前活动图仍是“功能回路 + 局部连接样本”，完整连接图继续只在仿真端运行。

导出按钮现在生成 `match-observations/v2`：每个样本包含 `senses`、`brain`、回路活动、固定 canonical 神经元样本、身体状态和食物余额，顶层包含事件时间轴与 receipt 哈希。它明确说明固定样本不是完整 165,122 神经元 trace；完整原始文件仍以不可变 run asset 提供。

这一步让“感觉输入 → 神经活动 → 身体行为 → 结果”有了同一份记录，但还没有宣称完成第一阶段最终验收：需要在 30 秒以上场景中生成一条确实发生食物摄取的公开生命回放，并完成部署后的肉眼检查。下一步优先跑这条可观看的觅食样本，而不是继续扩展后台接口。

## 统一研究对象：可演化的数字果蝇

Fly Arena 的基本研究对象不是一个抽象控制器，而是一只带有真实连接组来源、可修改神经参数、身体、感觉和生命记录的数字果蝇。公开的果蝇连接组提供 canonical brain：神经元、突触数量、兴奋/抑制方向和脑区归属保持可追溯；用户或 AI 提交的是在此基础上的 `FlySpec`，不能覆盖原始连接组。

连接权重从 canonical 值开始：

```text
W0(i,j) = synapse_count(i,j) × sign(i,j) × base_strength
W(i,j)  = W0(i,j) × mutation(i,j)
```

普通用户通过嗅觉、视觉、记忆、探索、攻击、逃避和运动等功能回路编辑器修改回路倍率；高级用户按神经元类别、区域、左右侧或边组编辑；AI 和研究者可以提交完整的权重差分、神经元内在参数和可选的学习规则。三种入口最终都编译成同一种 `FlySpec`，因此网页设计、API 提交和自动演化可以直接比较。

每份 `FlySpec` 都有 mutation budget。预算按照连接重要性和 `abs(log(scale))` 计费，强化或削弱不能无限叠加；预算、修改前后权重摘要和约束版本会进入不可变记录。这样优化目标必须在“改变哪里”和“保留什么能力”之间做出策略选择，而不是把所有兴奋权重调到最大。

## 人、AI 与演化算法的同一条路径

用户可以在网页里设计一只果蝇，也可以选择算法在沙箱中生成后代。第一批内置算法包括随机搜索、遗传算法、交叉熵方法（CEM）、模拟退火、Adam/BPTT（仅对可微代理或 rate 模型开放）和一个自定义算法接口。算法不是隐藏的后台实现，而是实验配置的一部分：名称、版本、随机种子、父代、mutation budget、候选数量、评估地图和停止原因都要随实验写入生命账本。

每个候选必须在真实竞技环境中评估，同时记录任务得分、摄取数、路径长度、能量消耗、传感器使用、失败事件、神经目标损失和行为目标损失。神经响应更接近目标不能自动等于竞技表现改善；排行榜只接受通过相同地图、物理、脑模型、解码器和随机种子协议产生的可复现实验。

演化记录采用谱系图而不是只有“第几代”的计数：每个样本有稳定 ID、父样本 ID、算法、变异摘要、完整 `FlySpec` 哈希、回放资产哈希和裁判结果。初代是明确的 `generation: 0`，每个后代的代数等于父代最大值加一；没有父代的候选不能被显示为第三代或被伪造为已进化样本。用户可以沿谱系查看每一代的脑图差异和真实比赛回放。

## Arena 是研究沙箱，也是可解释的比赛

地图必须是三维、可渲染且有明确规则的实验环境，而不是一维轨迹播放器。觅食地图先提供叶片、果实、障碍物、多个气味源、能量消耗和遮挡；随后加入资源争夺、双体接触/攻击、逃避和合作任务。每个地图版本定义传感器、动作、碰撞、摄取、越界、能量和计分规则，并把规则版本绑定到回放。

每一场比赛都形成一个可审计的生命样本：环境状态、果蝇身体、感觉输入、脑区和采样神经元活动、动作解码、行为事件、分数和失败原因在同一时间轴对齐。事件必须能跳转到三维场景和脑图，例如“左侧气味上升 → 嗅觉回路活动上升 → 转向 → 口器接触 → 摄取”。没有经过生理模型验证的几何视觉或物理接触信号只能作为带 provenance 的观测被动记录，不能被 UI 误称为真实视觉/触觉神经输入，也不能悄悄改变神经行为基线。

## AI 贡献与 NyxID 接口边界

AI 贡献使用和网页设计完全相同的 `FlySpec`、评估和回放接口。AI 可以读取规则、连接组摘要、公开谱系和历史比赛，提交候选、启动沙箱实验、读取事件/脑活动并上传分析；它不能修改 canonical connectome、裁判规则或历史账本。AI 的提示、设计理由、使用的算法和结果摘要作为实验元数据保存，便于回答“AI 到底贡献了什么”。

NyxID 只负责一次性授权后的身份、权限和额度，不进入连接组仿真核心。预留的接口边界为：

```text
POST /api/v1/auth/exchange       # 一次性授权码换 Arena session
GET  /api/v1/me                  # 用户或 AI agent 身份
POST /api/v1/flies                # 提交 FlySpec
POST /api/v1/experiments          # 启动演化/评估沙箱
GET  /api/v1/experiments/:id      # 状态、日志和资源用量
GET  /api/v1/replays/:id          # 回放、事件、脑活动和 receipt
```

MVP 可以用本地 demo session；NyxID 接入时只替换身份适配器。权限至少区分 `fly:submit`、`arena:run`、`replay:read`、`lineage:read` 和管理员能力，GPU 时间、并发数和私有样本按 agent 记账。前端登陆应是一次性授权链接或短码，避免用户先理解复杂的账号系统。

## 生命账本与 TruTuring 的可借鉴部分

TruTuring 的可借鉴点是把运行过程当作可验证的 harness：输入、工具、版本、输出和判定必须形成结构化证据，治理规则应能在运行前检查、运行中记录、运行后复现。Fly Arena 将其映射为生命账本：`FlySpec`、connectome hash、map、seed、physics、brain model、decoder、算法、资源节点、事件文件、回放和 judge receipt 组成一条不可变实验链。

账本记录事实和来源，不替研究者解释因果。裁判只能验证结构、边界、规则和哈希一致性；神经科学解释必须标记为观测、相关性或研究者假设。版本化 CI 要求前端测试、后端测试、receipt 校验和最小真实回放通过后才能合并；每个增量尽快合并到主分支并发布可使用的版本，避免把工程流程变成与科研无关的逐文件审批。

## 资源与工程路线

Mac Studio 运行交互 API、网页和轻量预览；4060 节点优先运行全图神经计算、30–60 秒生命回放、批量候选评估和渲染。GPU 任务通过队列和单节点锁串行调度，前端能看到排队、运行、失败和产物链接。每次完成一条可观看的回放就发布一个可用增量，不等待所有竞技模式完成。

先保持 Python、MuJoCo、NumPy/Numba 和 Three.js 的接口稳定。只有 profiling 明确指出神经计算热点，且 Python 版本已有可复现实验和测试，才把独立热点迁移到 C++/CUDA；C++ 不是第一阶段的交付条件。

1. 修正观测与神经输入的边界，保持已校准的 odor-only 行为基线；固定脑图显示样本，使活动按 canonical neuron ID 映射，未采样节点显示为未采样。

3. 已在 4060 上生成一条 30 秒、确实发生接触和摄取的新生命回放，并部署到 Mac Studio；下一步需要完成浏览器肉眼检查与更复杂地图的同等验收。
4. 合并设计页的 FlySpec 与 mutation budget，提供固定刺激预览和真实环境评估。
5. 接入随机搜索、遗传算法和 CEM 的可选实验配置，展示至少两条真实演化谱系。
6. 增加双体竞技、脑图对比、AI 提交和 NyxID 身份适配器。

每一步的完成条件都是用户可以打开页面观看、拖动时间轴、看到三维行为与脑活动对应，并下载 receipt；只有新增接口、统计分数或漂亮但没有真实数据的回放不算完成。
