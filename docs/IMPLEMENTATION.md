# 实施与部署规格 v0.1

核查与设计日期：2026-09-15。状态：DRAFT，待本地 agents 实现。本文件规定平台责任；实验步骤与验收见 [EXPERIMENTS.md](EXPERIMENTS.md)。

## 1. 产品边界

平台提供地图编辑、环境、共同身体/传感器/动作规范、权威物理、接触裁判、死亡与胜负、参赛接口和网页回放。玩家在自己的机器运行脑模型、规则程序或其他 controller。首版固定身体，允许名字与外观变化。真实连接组、复眼、任意形态、飞行、自研训练平台和不受信任的托管代码均不属于首版。

生存、HP、能量和冲撞是公开游戏规则，不是实验验证的果蝇生理。不得据胜率推断自然果蝇的攻击性、真实寿命或连接组模型优越性。

## 2. 架构和机器分工

```text
玩家自己的 controller  ---- WSS ----> 远端 API <---- HTTPS/WSS ---- 观众浏览器
                                         ^
                                         | 本地主动建立出站连接
                                         |
                                本地 4090 主机上的 worker
                                         |
                                 一个 MuJoCo 世界
                                  地图 + 身体A + 身体B
```

远端 Linux 服务器运行 Caddy、一个 FastAPI 进程、PostgreSQL 和回放存储；本地主机运行可信 worker、公共低层身体控制器与物理世界。浏览器负责编辑和渲染，玩家只请求动作。平台不向玩家分发任何世界写权限。

网站和历史回放不依赖本地主机在线。本地主机离线时排队并显示 worker offline；进行中比赛按照 E07 中断处理。本地不映射家用路由器端口，不公开 SSH、Jupyter、Docker API 或 heca。

前端采用 React/TypeScript/Vite + Three.js/React Three Fiber；API 采用 FastAPI；数据和任务用 PostgreSQL。首版保持 API 单进程，否则必须先实现跨进程 WS 路由。任务用短事务领取并立刻释放数据库锁，不持锁运行仿真。上游能力依据见 [S5-S8](SOURCES.md)。

## 3. 四个网页与单一地图源

`/arenas` 地图大厅；`/arenas/:id/edit` 拖拽编辑；`/matches/:id` 观战和回放；`/agents` 注册身份、连接状态和 SDK 接入说明。中央画布优先，不开发脑图编辑器。

编辑器支持选择、平移、旋转、缩放、复制、撤销、保存草稿和发布。首版只接受静态 box、两个出生点和轴对齐危险区。地图 JSON 由同一版本编译为 Three.js 场景和 MuJoCo 几何。

外部单位毫米，右手系，Z 向上；四元数顺序 wxyz；box 的 `size_mm` 为完整边长。Three.js 的 xyzw 与 MuJoCo 的 box 半尺寸只在适配器中转换。位置、速度、角速度和角度均在 profile 中明确单位。上游身体 API 的毫米和四元数约定见 S1/S2。

发布要求：地图最多128个物件、16个危险区、正好2个出生点；正尺寸、有限数值、唯一ID、单位四元数；限制总包大小为256 KiB；拒绝脚本、外部URL、原始MJCF和未知字段。后端还须用真实身体检查出生重叠、越界、危险区和初始稳定性。JSON Schema 无法独立证明这些性质。

服务端存储发布后的确切字节并计算 SHA-256；worker 对下载字节验哈希。比赛绑定不可变 map/profile/rules/assets 版本。草稿修改不改变已开局的世界。碰撞、遮挡几何和展示误差由 E01 验收。

## 4. 参赛协议

SDK 的目标接口为 `reset(context)` 与 `act(observation)`，需要 agents 实现。玩家通过平台签发的短期 token 接入 WSS，不提供服务器需要回访的 URL。

消息流程：`join -> reset -> reset_ack -> observation/action* -> result`。每条动作携带 match_id、attempt_id、slot、tick；连接本身绑定 match/slot，字段不能改变授权。每个 tick 的首个合法动作生效；相同重复请求幂等，冲突重复、旧/未来 tick、未知字段和非法数值拒绝。首次非法动作不占用有效动作位置，但计入限流。

初始统一 profile：`nmf-standard/1.0`、`rays-proprio/1.0`、`drive-combat/1.0`、`survival-ram/1.0`。这些是本项目计划定义的标识，不是上游已有实现。

观测包含自己 HP/能量、局部线速度、角速度、固定顺序42维腿部关节角、6个足部接触和24条水平遮挡射线。42维须与所选身体的实际 DOF manifest 一一核对，不得硬凑长度。射线角度 `2*pi*k/24`，局部+X为正前方，身体局部坐标原点和固定高度由 profile 在校准时冻结；最大射程30 mm。射线只返回最近命中类别/距离，不返回遮挡后对手位置或对手内部状态。自体几何排除策略和尸体类别也需冻结。

动作固定为 `drive:[0,1]`、`turn:[-1,1]`、`attack:none|ram`。例如：

```json
{"type":"action","match_id":"m1","attempt_id":"a1","slot":"a","tick":12,"action":{"drive":0.7,"turn":-0.2,"attack":"ram"}}
```

公共驱动器将动作转成有上限的左右下行信号，低层每个物理步更新关节/附着控制。上游转向教程可作底座，冲撞必须自行实现和校准，不能直接修改身体位置或给对手扣血 [S3]。

连接组参赛者自行完成观测编码、脑活动计算与动作读出；平台提供输入输出一致性测试，不声明完整脑模型已经接入。公开远程赛道为 `remote-open`，无法验证对方真实算法、算力、人工干预或第二账号偷看直播。严格排名另设未来的审核托管赛道。

## 5. 时间、裁判和公平

physics_dt=0.0001 s、decision_dt=0.1 s、snapshot_dt=0.05 s。全部采用整数步计时：1000步/决策、500步/快照。一个决策轮双方看到同一模拟时刻各自可见状态，云端并行发送观测并收动作，动作一起生效。网络等待期间世界、体力、冷却和年龄暂停。

公共 wall deadline 初值1秒；连续5轮未返回合法动作技术判负。一次无动作使用 zero action；双超时为双技术失败，不是同时游戏死亡。gateway到worker链路异常须中断本轮，不算玩家迟到。测试中必须以gateway单调时钟记录发送、接收和截止，不依赖跨机时间戳减法估计延迟。

初始规则数值：HP=100，energy=100，回复2单位/模拟秒，满drive耗1单位/模拟秒；ram耗5，伤害10，准备500物理步、有效1000步、恢复1500步，自攻击开始至下次可启动间隔10000步。按一次事件请求启动；持续发送ram只能在能量和冷却允许时开启新attack_id。能量先检查/扣除启动成本，运动消耗/回复按各物理步结算并夹紧到[0,100]。

命中要求处于有效窗口、真实前部身体接触、目标为对手、方向合格；一次attack_id对同一目标最多一次伤害。额外的驱动倍率、前部geom集合、朝向阈值须在预实验校准后写入不可变 rules/profile，并重新验收。未校准状态标记 BLOCKED，不发布为正式规则。

每个物理步先收集合法攻击/危险区事件，再统一结算双方HP，之后判死。HP=0或身体指定参考点进入致死区为游戏死亡。危险区参考点固定为胸部主体参考点，不以任意触角越界判死。尸体保留碰撞体；死亡后关闭动作控制及主动驱动/附着，避免位置伺服继续做功，具体关节无驱动状态应由身体适配层验证。

一存活一死亡为存活方胜；同一步双死亡为draw；120秒模拟时间上限双方存活为draw。技术判负、基础设施中断、simulation_error分别记录。NaN、状态爆炸或碰撞异常使对局无效，禁止修剪状态后继续算胜负。胜率不能把中断当死亡或默默删掉失败局。

## 6. 回放、租约与网络

worker以5秒heartbeat维持60秒TTL租约，每次attempt有递增fencing token。写入、块上传、完成均要求当前active_attempt；旧worker迟到结果不能覆盖新局。回放分块、带SHA-256，先临时写入，收齐后原子发布；重复同哈希上传幂等，冲突拒绝。

重启后首版从reset重新开始，不声称恢复玩家脑内记忆。最多一次自动重试，记录原失败attempt，避免静默重试改变对局分布。比赛失败比例以所有attempt为分母。

保存动作、初态、驱动器状态、随机源、地图与引擎选项哈希、资产manifest、实际分段姿态与事件。观众流可丢弃过时快照，可靠事件和最终回放不能丢。每1秒模拟时间分块，始终包括最终状态，即使未对齐快照周期。观察员只能读公开快照，不能读双方私有观测。

网页用真实body segment变换，不能用中心点加任意步行动画代替身体姿态。快照以20Hz模拟时间采样，网页可30FPS以上插值；数据未到达显示等待，不伪造击中。播放记录与重跑物理分别验收。跨GPU和跨求解器不承诺位级一致，完整状态与warmstart限制见S4。

## 7. 部署顺序和要交付的运维文件

假设远端有Linux公网入口，本地4090主机可运行Linux/Docker；OS、显存和CPU/RAM以E00测量为准。4060仅作可选复测。Windows/WSL2、EGL和GPU容器路径需要单独验证。

| 位置 | 服务 | 持久化 | 暴露 |
|---|---|---|---|
| 远端 | Caddy + FastAPI单进程 + PG | 证书、数据库、地图、资产与回放 | 公网80/443；管理入口限源 |
| 本地 | 可信worker + 单局进程 | 资产cache、编译cache、回放spool | 只主动出站，无公开端口 |
| 玩家 | 自己的controller | 自己的模型和日志 | 出站WSS |

Agent D须实现 `deploy/compose.remote.yaml`、`deploy/compose.worker.yaml`、`deploy/Caddyfile`、两份env模板、secrets读取、卷初始化、备份/恢复脚本；本PR不含可直接启动的应用镜像。

部署具体次序：

1. E00只读预检：OS、CPU、RAM、磁盘、nvidia-smi、Docker/Compose版本、出站TLS；不改现有系统。
2. 锁定Python3.12、FlyGym v2.1.0及相应MuJoCo依赖，记录实际commit和全部资产许可 [S1]。运行上游CPU示例，再完成E02。
3. 构建前端/API/worker可信镜像并写image digest。远端设置域名，Caddy负责证书和WS代理；数据库5432和API8000不映射公网 [S5-S8]。
4. 为数据库、回放、cache/spool初始化最小权限；容器非root、只读rootfs，可写路径明确。空卷默认root所有权会导致worker失败，必须进行真实空卷启动测试。
5. 本地worker配置 `API_ORIGIN`、`WORKER_ID`、token文件和 `MAX_CONCURRENT_MATCHES=1`。CPU路径不要求GPU容器访问；可选GPU路径先验证Container Toolkit，再按设备ID分配，不自动重启用户Docker [S9]。
6. E05重复局域网与公网路径；E07断开worker、过期token与API重启；E08回放；E10观众压测和独立备份恢复。停止heca，服务仍正常。

worker认证、玩家token和管理会话分离。SDK认证token放文件或交互输入，不放URL、命令行明文或普通日志。内部API名字含internal不代表安全，仍经公网TLS、独立认证和限流。地图/请求体限大小，拒绝非有限值及过大数组；浏览器采用Origin/CSRF检查。不得把远程代码沙箱部署到有研究数据和私钥的4090主机。

4090容量未知。E09先比较CPU单场与GPU单场，再4/8场。记录纯步进、身体驱动、传感、网络等待、序列化、峰值显存/内存及cold compile。GPU教程只支持同模型多世界，并展示noslip选项被修改，必须保存实际编译选项，不能默认CPU/GPU同一个规则后端 [S10]。远程批处理还须证明某一世界等待网络时不会推进它的模拟时间；缺少每世界暂停/掩码能力则GPU只用于离线受控批量。

## 8. heca的位置

此前核查的heca公开仓库仅分发二进制，源码在私库；它可作为可选远程开发入口 [S11]。不依赖它调度比赛、认证玩家或托管GPU。关闭heca不影响竞技服务是上线检查项；本PR没有安装、审计或验证heca。
