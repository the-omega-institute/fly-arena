# 开发与交付

`main` 是可运行版本。每个 PR 只完成一个能解释的产品能力或一个明确缺陷；从最新 main 开始，不再叠加长链草稿。默认直接开可评审 PR。

## 每个 PR 的 CI

- 后端：锁定依赖，运行 API、权重预算、神经递推、任务状态、真实短物理测试和回放测试。
- 前端：锁定 npm 依赖，运行交互逻辑测试、TypeScript 检查和生产构建。
- 失败先修，全部通过后及时合并。构建产物由 CI 保存，部署使用该版本。
- CI 取消同分支过时任务，失败输出测试报告。不开多轮角色评审，不重复逐文件哈希。

本地对应命令：

```sh
uv sync --locked --group dev
uv run pytest -q -m "not integration"
cd web
npm ci
npm test
npm run build
```

## 科研实验与 CI 分工

CI 保证代码按契约工作。它不以合成小图测试宣称生物学结论，也不在每次 PR 下载整个图谱和运行长比赛。

真实科研运行使用版本明确的 connectome 和 FlySpec，在实际节点执行。每轮记录：个体与父代、权重干预、环境/赛制、seed、神经活动、行为轨迹、比赛结果和选择理由。比较世代时保持评测条件一致；改环境时明确开启新实验。

完整图谱集成测试在准备好数据的节点运行：`uv run pytest -q -m integration`。它检查真实数据接入，不替代比赛或演化实验。昂贵实验按研究问题运行，结果与工程 CI 分开标注。

## 发布

PR 合并后同步远端，确认首页/API、一个实际用户流程和当前版本。小改动直接发布；不因未完成的科研路线积压已完成的平台功能。NyxID 的真实接入仍等待用户后续联调。
